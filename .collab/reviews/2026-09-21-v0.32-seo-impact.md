# Did v0.32.0 undo earlier SEO work? (2026-09-21)

Owner's question, after v0.32.0 (Night marketing surface + Phase 2a) went live:
"我们的 SEO 之前的进展会不会因为这次修改而失效呢？"

**Verdict: no.** Everything a search engine indexes or ranks on is either
unchanged or measured with no regression. One real cost did turn up: a font
preload that Night made useless. It is fixed on the branch, not yet deployed.

## What did change on the landing

- **Removed.** The v0.31.0 `ProductFrame`. It was `aria-hidden`, but its
  text was in the DOM on all 11 locale landings: an English excerpt of
  Alphabet's Q4 2025 release (headline, dateline, lead-in, the cited sentence,
  the filename). On ten non-English pages that was off-topic English, so losing
  it is neutral to positive. The frame's one visible sentence,
  `landing.frame.caption` ("Every answer links to the sentence it came from, on
  its page."), is retired; the h1 now carries that message. The key is unused
  in 11 locales and has been left in place.
- **Added.** Visible text: the answer card's question, answer and source line, plus
  the Quote Finder footnote. A screen-reader-only description of the picture. The
  citation field itself is a canvas, not text.
- **h1 in eight locales.** The old h1 ("chat with any PDF in seconds") had the
  word PDF; the new claim ("every answer cites the exact page") does not. The
  search titles there still say "chat with any PDF…".
- **Gradient h1.** `color: transparent` + `background-clip: text` under
  `@supports`. It is still text in the DOM and visible on screen. Chrome does
  not report it as an LCP candidate; the lede is (see below).

## Core Web Vitals (lab)

Tool: `frontend/scripts/design-audit/cwvcheck.mjs` (CDP; phone = 412×823, 4×
CPU, Lighthouse's applied slow 4G 562.5 ms RTT / 1.47 Mbps; desktop = 1350×940,
40 ms / 10 Mbps). The public PageSpeed Insights API was over its daily quota,
so CrUX field data could not be checked. With traffic near zero the origin
almost certainly has none, in which case Core Web Vitals cannot move rankings
in either direction today.

**Before vs after.** Local `next start` of each build, same machine, same
emulation, 5 runs, median:

| | v0.31.0 | v0.32.0 | v0.32.0 + Fraunces fix |
|---|---|---|---|
| `/` phone LCP | 2388 ms (h1) | 2376 ms (lede) | 2248 ms |
| `/pricing` phone LCP | 2404 ms | 2412 ms | 2256 ms |
| CLS | 0 | 0 | 0 |

No regression. The LCP element moved from the h1 to the lede, at the same time.
The fix (below) puts both pages ahead of v0.31.0.

**Production:**
- `/` on a phone: LCP ≈ 3.19 s (the lede), CLS 0, TBT ≈ 0.
- `/` on desktop: LCP ≈ 0.68 s, CLS 0.
- `/ja`: CLS 0.005 on desktop and 0.0175 on a phone, both from the cookie banner.
- The answer card is at opacity 0 until the citation is marked. It never became an LCP candidate.

## The one real cost, fixed on the branch

The root layout preloaded Fraunces on every route: normal 121 KB plus italic
149 KB. Since Night, no page shows Fraunces when it loads. `document.fonts`
on `/` and `/pricing` reports only IBM Plex Sans, IBM Plex Mono and Geist in
use. On app routes (`/auth`, `/billing`, `/profile`, `/collections`, a 404) it reports
only IBM Plex Sans and Sora; Tailwind's `font-serif` maps to Sora / Plex Sans, not
Fraunces. The one remaining user is the app's citation popover (italic).

In v0.31.0 this preload paid for itself: Fraunces set the paper display type.
Night turned it into dead weight, and v0.32.0 also added Geist (70 KB, used).

**Measurement.** Production A/B on a phone, interleaved, 6 pairs per page, B =
the two Fraunces files blocked:

| | preloaded (median) | blocked (median) |
|---|---|---|
| `/` | 3190 ms | 3016 ms |
| `/pricing` | 2954 ms | 2750 ms |

Every one of the 12 pairs was faster with the files blocked.

**Fix.** `preload: false` on the Fraunces declaration in `app/layout.tsx`. The
`@font-face` and `--font-fraunces` are still emitted, so the popover fetches
the face on first open; the trade-off is a one-time swap from the fallback face
in that popover. `tests/landing-night.test.cjs` guards against the preload
coming back (probe: removing the line fails it).

Verified on a build:
- 5 font preloads on marketing pages (was 7) and 4 on app pages (was 6).
- No Fraunces request at load.
- An italic `var(--dt-serif)` element (what the popover renders) fetches the
  italic file, and the face loads.
- The metadata of all 416 pages is unchanged (empty diff).

Sora (25 KB, the app logo) is also unused on marketing pages. It is left
preloaded because app pages show it above the fold.

## For the owner: the landing search titles (Phase 2b m3/m4)

Rendered `<title>` today (English `/` hardcodes "DocTalk — AI Document Chat
with Cited Answers"):

| | `<title>` |
|---|---|
| zh | 与任何 PDF 即时对话 \| DocTalk |
| ja | あらゆるPDFと 瞬時にチャット \| DocTalk (stray space from the h1's line break) |
| ko | 모든 PDF와 즉시 채팅 \| DocTalk |
| es / fr / it | Chatea con cualquier PDF en segundos / Discutez avec n'importe quel PDF en quelques secondes / Chatta con qualsiasi PDF in pochi secondi |
| ar / hi | تحدث مع أي PDF في ثوانٍ / किसी भी PDF से तुरंत बात करें |
| de / pt | Jede Antwort zitiert die genaue Seite. / Cada resposta cita a página exata. (no "PDF"; trailing period) |

The de/pt titles are not new. Their h1 changed on 2026-03-16 (`aedd005`),
before `/de` and `/pt` existed, so those URLs have had these titles since
launch. Their original translations were "Chatten Sie mit jedem PDF in
Sekunden" and "Converse com qualquer PDF em segundos".

**Options.** Each changes search titles, so the owner decides:

- **A. Whitespace only.** Store every `landing.metaTitle` on one line. Only
  ja's `<title>` changes (the stray space goes). de/pt keep titles without a
  keyword.
- **B. A, plus de/pt back on the eight-locale message**, using their own
  February translations. Three `<title>`s change: ja, de, pt.
- **C. One message in all ten.** Translate the English title ("AI document chat
  with cited answers"). All ten `<title>`s change, and they match the product's
  differentiator and the English page.

The `\n` guard test (no `*.metaTitle` contains a line break) lands together
with whichever option is chosen.
