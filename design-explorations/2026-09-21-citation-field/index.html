首页原型 · 三选一

三个方向都是可交互的真实网页，不是效果图：动画会实际播放；鼠标移到文档上，会有一小块“灯光”跟着光标走。建议点“全屏打开”逐个看，再用“重播”看入场动画。

三个方案共用：同一段文案（标题 “Every answer cites the exact page.”，一个主按钮）；同一个签名视觉——引文聚光：一页真实文档（Alphabet 财报第 1 页，逐字原文）处在暗处，一束光扫下来，停在被引用的那句话上，荧光笔划过，角标 “1” 弹出，然后出现带 [1] 的回答。这就是产品本身：每个回答都指向原文的确切位置。
三个方案的区别：只在“舞台”——材质、光线、字体和配色。

A · 纸

保留暖纸 + 赤陶品牌，把纸当成真实的物体：台灯下、桌面上的一整页纸（第二版，已按 Fable 评审修改）
全屏打开

它好在哪

在 v0.31.0 刚上线的体系上加码（Fraunces + Plex、赤陶色），不推翻任何决定；app 迁到暖纸的计划照常。倾斜的纸、纸的投影、台灯的光晕都有实物感，温暖、安静，像一个认真读文件的工具。

代价 / 风险

“米色 + 衬线 + 赤陶”是很多 AI 生成网站的默认审美。能不能跳出这个套路，全靠签名视觉和质感撑着；如果细节做粗了，会退回“又一个米色 SaaS”。

落地工作量

最小。token 和字体都已经在 editorial.css 里；主要是新做 Hero（画布组件 + 纸张和卡片），再改几节的节奏与留白。

B · 夜

暗色、电影感，像 memorable.sh / apple.com 发布页：只亮一盏灯的阅览室
全屏打开

它好在哪

冲击力最强，第一眼最“有设计”。整屏文档在暗处，琥珀色的光落在那句引文上，是三个方案里最戏剧化、最难忘的画面。琥珀色取自 DocTalk 的引文色，刻意避开 AI 工具都在用的紫色光。

代价 / 风险

推翻 09-20 “保留暖纸”的决定，需要一套新的深色 token 和新字体（Geist）。长时间读文档不适合纯暗底，app 本体仍要浅色，营销页和 app 又会变成两套表面，而这正是 09-20 决定要消灭的。

落地工作量

中到大。营销层所有页面都要换舞台，而不只是首页（否则从首页点进 /pricing 会从夜晚跳回白天）；深色下的对比度也要重新校验一遍。

C · 日光

apple.com 产品页的语法：近白底、单一字体、居中宣言，产品界面本身就是主视觉
全屏打开

它好在哪

最“苹果”，也最诚实：主视觉就是真实的阅读器，左边是文档，右边是回答，窗口带 3D 入场。营销页和 app 最容易统一，因为 app 现在本来就是 zinc + 蓝。

代价 / 风险

放弃暖纸和赤陶品牌；蓝色按钮 + Inter 会和无数 SaaS 撞脸，辨识度最低。这也直接违反了 frontend.md 里“不要再提中性/蓝色重塑”的记录（是你这次要求一起做的，所以放进来比较）。

落地工作量

中。营销层要整体换 token；好处是 app 的 Phase 3–4 反而会变简单。

推荐：A（Fable 独立评审同意，排序 A > B > C）

这次问题的根源不在配色，而在首屏没有一个只属于 DocTalk 的画面，而且没有光、没有纵深、没有动效。三个方案里真正起作用的是“引文聚光”，它在三个舞台上都成立。A 是唯一不推翻已上线体系、也不把营销页和 app 拆成两套表面的方案。

Fable 的原话要点：A 的第一版是三个里第一眼最弱的，推荐成立的前提是修掉它指出的问题。这些问题已经按它的意见改完，现在看到的 A 是第二版：纸张改为整页、投影真正画出来、桌面调深、灯光改成“纸在阴影里”、回答卡片暖色化并用细线连到角标，动画顺序改成“问题 → 扫描 → 划线 → 角标 → 答案”。

如果你看完仍然想要 B 那种暗场的冲击力，Fable 给的退路是：只把首页首屏做成一段深色带，用已经上线的深色暖纸 token（#171614），仍然留在同一套纸面体系里。这比整站换成 B 代价小得多。
